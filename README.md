# NetGuard — межсетевой экран с фильтрацией пакетов

Файрвол для Windows: перехват трафика, разбор заголовков IP/TCP/UDP/ICMP,
список правил с приоритетами, журналирование и веб-панель управления.

Реализовано по техническому заданию «Разработка программного файрвола
(межсетевого экрана) с фильтрацией пакетов», п. 3.1 (базовый уровень).

---

## Как это работает

Фильтрация пакетов выполняется **в ядре ОС**, а обычное приложение к ядру
доступа не имеет. Поэтому используется **WinDivert** — подписанный сторонний
драйвер, который позволяет из пользовательского режима перехватывать пакеты
и возвращать их в сетевой стек либо **не возвращать**, отбрасывая.

```
   ┌──────────────┐   WinDivertOpen   ┌─────────────────────────┐
   │  netguard    │◄──────────────────│ драйвер WinDivert       │
   │  (user-mode) │  пакеты           │ (kernel-mode, подписан) │
   └──────┬───────┘                   └─────────────────────────┘
          │  разбор заголовков → правила → решение
          ▼
   разрешить → WinDivertSend (пакет уходит дальше)
   запретить → ничего не отправляем (пакет отброшен)
```

Альтернативные варианты и почему они не выбраны:

| Вариант | Почему не выбран |
|---------|------------------|
| WFP callout-драйвер (C/C++ в ядре) | «Каноничный» путь Microsoft, но нужен Windows Driver Kit, подпись драйвера и отключение Secure Boot. Намного больше работы, чем весь остальной проект |
| Только захват (Npcap, `SIO_RCVALL`) | Умеет только читать пакеты. Правила можно вычислять и логировать, но **блокировать нельзя** — это IDS, а не файрвол |

> **Требуются права администратора.** Драйвер загружается в ядро, поэтому без
> повышения прав перехват невозможен. Программа проверяет это при старте и
> выводит понятную инструкцию.

## Сборка и запуск

```powershell
cd src
dotnet build NetGuard.slnx -c Release
dotnet test  NetGuard.slnx                        # 73 теста
```

Готовый исполняемый файл:

```
src\NetGuard.Cli\bin\Release\net10.0-windows\win-x64\netguard.exe
```

> В каталоге вывода обязательно присутствуют `WinDivert.dll` и `WinDivert64.sys`.
> В проекте задан `RuntimeIdentifier=win-x64`: без него нативные файлы не
> попадают в `deps.json`, и программа падает с `DllNotFoundException`
> уже при первом запуске от администратора.

> `WinDivert.dll` и `WinDivert64.sys` исключены из Git: они подтягиваются
> из NuGet-пакета `Native.WinDivert` при каждой сборке.

### Запуск от администратора

```powershell
# Проверить конфигурацию — права администратора не нужны
.\src\NetGuard.Cli\bin\Release\net10.0-windows\win-x64\netguard.exe check

# Запуск с веб-панелью (http://localhost:8080)
.\src\NetGuard.Cli\bin\Release\net10.0-windows\win-x64\netguard.exe run --web
```

Конфигурация ищется рядом с программой; путь можно задать явно:
`netguard.exe run --web -c .\rules.example.json`.

При первом запуске `rules.json` создаётся автоматически. В репозитории лежит
только шаблон `rules.example.json` — локальный `rules.json` не коммитится.

### Запуск от администратора

Перехват пакетов требует повышенных прав: драйвер загружается в ядро ОС.
Без них панель откроется, но покажет «остановлен» и ничего не будет фильтровать.

```powershell
Start-Process -Verb RunAs `
  -FilePath ".\src\NetGuard.Cli\bin\Release\net10.0-windows\win-x64\netguard.exe" `
  -ArgumentList 'run','--web'
```

| Команда | Описание |
|---------|----------|
| `run` | запуск перехвата и применение правил |
| `check [файл]` | проверка конфигурации без перехвата трафика |

### Параметры `run`

| Параметр | Описание |

| `-c, --config <путь>` | файл конфигурации (по умолчанию `rules.json` рядом с программой) |
| `-w, --web [url]` | веб-панель на `http://localhost:8080` |
| `--no-web` | без веб-панели |

| `--log-allowed` | писать в журнал и разрешённые пакеты |
| `--default-action <a>` | `allow` или `deny` |
| `-v, --verbose` | подробный вывод |

### Управление в консоли при работе

| Клавиша | Действие |
|---------|----------|
| `s` | статистика |
| `r` | правила со счётчиками совпадений |
| `l` | последние события |
| `f` | перечитать `rules.json` без остановки |
| `q` | выход |

## Формат конфигурации (rules.json)

```json
{
  "defaultAction": "Deny",
  "capture": {
    "filter": "(outbound or inbound) and (ip or ipv6) and not loopback and not multicast",
    "includeLoopback": false,
    "priority": 0,
    "queueLength": 8192,
    "queueSize": 33554432
  },
  "logging": {
    "enabled": true,
    "directory": "logs",
    "fileNameTemplate": "firewall-{date}.csv",
    "logAllowed": false,
    "logDenied": true,
    "memoryBufferSize": 1000
  },
  "rules": [
    {
      "name": "Разрешить HTTPS (исходящий TCP/443)",
      "action": "Allow",
      "protocol": "Tcp",
      "direction": "Outbound",
      "destinationPort": "443",
      "log": true
    },
    {
      "name": "Заблокировать Telnet (TCP/23)",
      "action": "Deny",
      "protocol": "Tcp",
      "destinationPort": "23"
    }
  ]
}
```

### Поля правила

| Поле | Значения |
|------|----------|
| `name` | произвольное название, попадает в журнал |
| `action` | `Allow` или `Deny` |
| `protocol` | `Any`, `Tcp`, `Udp`, `Icmp`, `IcmpV6` |
| `direction` | `Any`, `Outbound`, `Inbound` |
| `sourceAddress` | `10.0.0.0/8`, `192.168.1.1`, `2001:db8::/32` или пусто |
| `destinationAddress` | то же |
| `sourcePort` | `80`, `1024-65535`, `80,443`, `1024-`, `any` |
| `destinationPort` | то же |
| `enabled` | `true` / `false` |
| `log` | писать ли совпадения в журнал |

Порядок правил в файле = порядок проверки. **Первое совпавшее правило выигрывает**,
несовпавшие пакеты обрабатываются по `defaultAction`.

`netguard check` предупреждает о пересекающихся правилах с разными действиями:
сработает только первое, а второе может оказаться недостижимым. Пара Allow/Allow
пересечением не считается — порядок на результат не влияет.

## Формат журнала (CSV)

```
timestamp,direction,protocol,src_ip,src_port,dst_ip,dst_port,length,action,rule_id,rule_name,fragment,reason
2026-10-09 14:57:03.123 +03:00,Outbound,TCP,93.184.216.34,443,10.0.0.5,51515,74,DENY,2,"Разрешить HTTPS (исходящий TCP/443)",-,правило #2 «...»
```

CSV выбран сознательно: файл без усилий открывается в Excel и в любом
просмотрщике. Значения с запятыми и кавычками экранируются по RFC 4180.

По умолчанию записываются **только заблокированные** пакеты — полный журнал
разрешённого трафика на обычной машине создаёт сотни мегабайт в час.
Разрешённые включаются опцией `--log-allowed` или полем `log` у правила.

## Веб-панель

Запуск: `netguard run --web` → <http://localhost:8080>

Панель показывает состояние, счётчики трафика, топ адресов, таблицу правил
со счётчиками совпадений и ленту событий. Обновляется раз в 2 секунды.

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET` | `/api/status` | состояние, статистика, ошибки |
| `GET` | `/api/stats` | только счётчики |
| `GET` | `/api/rules` | правила со счётчиками |
| `GET` | `/api/logs?tail=100` | последние события |
| `POST` | `/api/rules` | заменить правила (сохраняются в файл и применяются на лету) |
| `POST` | `/api/reload` | перечитать `rules.json` |
| `POST` | `/api/start`, `/api/stop` | запуск и остановка перехвата |

> Панель слушает **только loopback** и не имеет аутентификации: панель
> управления файрволом, доступная из сети, сама стала бы уязвимостью.

Правила применяются **на лету** — без остановки перехвата, поэтому изменение
не разрывает активные соединения.

## Реализованные требования (п. 3.1 ТЗ)

| № | Требование | Реализация |
|---|-----------|------------|
| 1 | Перехват пакетов на интерфейсе | `WinDivertCapture`, сетевой уровень, фильтр настраивается |
| 2 | Анализ заголовков IP, TCP, UDP, ICMP | `PacketParser` + тесты на синтетических пакетах |
| 3 | Фильтрация по IP | `CidrBlock`, IPv4 и IPv6 |
| 4 | Фильтрация по портам | `PortRange`, `CompositePortSet` (списки и диапазоны) |
| 5 | Фильтрация по протоколу | TCP / UDP / ICMP / ICMPv6 |
| 6 | Правила с приоритетами | `RuleSet.Evaluate`, первое совпадение выигрывает |
| 7 | Логирование | CSV с временем, адресами, портами, решением, правилом |
| 8 | Загрузка правил из файла | `ConfigLoader`, JSON с комментариями |

Дополнительно: веб-панель управления, горячая перезагрузка правил без остановки
перехвата, статистика трафика, поиск пересекающихся правил.

### Что осознанно не сделано

- **Stateful-инспекция** — требует отслеживания состояния соединений; в базовом
  уровне ТЗ не входит. Текущая модель — stateless (пятикортежная).
- **Rate limiting и защита от SYN/ping-flood** — п. 3.2, вне согласованного объёма.
- **Фильтрация по MAC-адресу** — п. 3.2. Поле разбора `IsEthernet` уже есть,
  правило можно добавить расширением `Rule`.
- **IPv6** в правилах поддержан полностью, но режим перехвата по умолчанию
  включает `ip or ipv6` — при необходимости IPv6 легко исключить фильтром.

## Особенности реализации

**Фрагменты не участвуют в фильтрации по портам.** У фрагментов, кроме первого,
транспортного заголовка нет, и чтение портов дало бы случайные числа.
`PacketParser` помечает такие пакеты, и правила с портами их не трогают.

**Контрольные суммы.** При включённом аппаратном offload суммы в перехваченном
пакете часто не рассчитаны. Перед возвратом пакета в стек суммы пересчитываются,
иначе получатель отбросил бы пакет как некорректный.

**Loopback исключён из перехвата по умолчанию.** Перехваченный пакет loopback
возвращается в стек повторно и может зациклиться. Включается флагом `--loopback`.

**Читаемость журнала важнее строгой типизации.** CSV открывается в Excel без
конвертации — для учебной работы это полезнее, чем JSONL.

**Скрипт не бросает исключений.** Пакеты приходят из недоверенного канала:
любая ошибка разбора трактуется как «не удалось разобрать» и не может остановить
фильтрацию. Это проверяется тестом на 3000 случайных байтовых последовательностей.

Тесты работают на синтетических пакетах, собранных по RFC, поэтому не требуют
прав администратора и реального трафика. Живой перехват на сетевом интерфейсе
автоматическими тестами **не проверяется** — для этого нужен запуск
с повышенными правами.
